# EH-05 acceptance evidence

The finale extends the existing controller and single WebGL renderer. It introduces an explicit `sequence` discriminator and `complete` playback state for later motion, context-recovery, and integration work. No separate animation clock advances descent.

## Acceptance mapping

1. The final leg crossfades into the existing authored Schwarzschild ray-integration shader during braking/settle. Lensed procedural stars, emission with orbital turbulence, disk opacity, Doppler-inspired asymmetry, and the photon ring use a bounded render target in the existing WebGL context. The scientific observer remains at 1,000 horizon radii; optical magnification is separate. The target follows adaptive resolution and is disposed with the renderer.
2. Observation retains the three sourced facts, Details, Previous, and bounded inspection. Positive wheel input at the route boundary does nothing. Legacy interior/horizon/descent links resolve only to observation. Entry requires the named Enter the event horizon button.
3. The controller interpolates log-radius with smooth quintic segments through 1,000/100/1.5/1/0.8 radii at 0/8/15/18/20 active seconds. A two-second quaternion blend from captured inspection aligns the inward-facing camera without crossing the center, including opposite inspection angles. The shader fades to black at radius one.
4. Horizon approach and radius in rₛ replace mph and ×c. Earth displacement follows the scientific observer offset. Tour distance stays fixed and the controller exposes no fabricated local relativistic speed. Pause, visibility pause, Resume and Finish descent use the existing playback commands.
5. The dark ending distinguishes total authored route length, light-equivalent route time, 236-second forward route playback, and optional 20-second descent. Details and the ending identify the disk/interior as illustrations rather than a survival/geodesic model.
6. Return to Earth uses the direct-navigation fade, resets elapsed time, view, velocity, effects time, wheel/pointer state and expanded rail, and focuses Next. Audio preference and the OS motion preference are retained. This is a replay, with no escape animation.
7. Numerical tests confirm the horizon derives from four million solar masses and is about 11.8 million km. Current source/calculations retain no Gaia mass, radius or tide thresholds; old IDs remain only in redirects.
8. `tests/finale.spec.ts` covers the controller contract and visible controls on desktop/mobile, plus real-time final braking/settle and uninterrupted descent, and a short static-fallback ending/replay.

## Verification results

- `npm run build` passed, including TypeScript. Changed-file Prettier checks and `git diff --check` passed.
- Diagnosed and resolved the full-route `horizon.spec.ts` stall under Playwright's virtual clock (`page.clock.install()`):
  - **Root cause:** Playwright replaces native `requestAnimationFrame` (which enforces compositor VSync / GPU backpressure) with an unthrottled 16 ms `setTimeout` loop (`realTimeTimer`). Because `gl.drawElements` is asynchronous on the Renderer CPU thread, `gsap.ticker` continuously queued full 3D and ray-marched black-hole frames into the software WebGL (SwiftShader) command buffer while `page.screenshot()` and `clock.runFor()` were waiting (`λ > μ`). When a subsequent step compiled a newly resident stop's shader and called `gl.getProgramInfoLog` (a synchronous GPU command-buffer barrier), the Renderer main thread blocked until hundreds of queued frames drained.
  - **Fix (`src/renderer.ts`):** Added a non-blocking WebGL2 fence sync (`gl.fenceSync(gl.SYNC_GPU_COMMANDS_COMPLETE, 0)` + `gl.clientWaitSync(fence, 0, 0) === gl.TIMEOUT_EXPIRED`). Scene-graph and diagnostic state still update on every tick, and every frame renders when the GPU fence has signaled; when the GPU is still busy rasterizing the previous frame, redundant in-flight or identical-state draw submissions are skipped while discrete resting/paused/complete state transitions still render immediately. Multi-tick fence waits also feed adaptive resolution scaling under mocked clocks.
- With the GPU backpressure fix in place, the complete headless Playwright suite passed with **zero failures**: **104 passed in 7.5 minutes** across desktop (`1440×1000`) and mobile (`390×844`) projects.
  - `tests/horizon.spec.ts` all-stop forward/reverse traversal with inspection and screenshots passed in **29.4 seconds** on desktop and **~25 seconds** on mobile (down from >600-second timeouts).
  - `tests/earth-moon.spec.ts` fake-clock wheel momentum and drag/pinch/hidden-tab tests passed in **8.3–10.7 seconds**.
  - All 10 `tests/finale.spec.ts` cases passed on desktop and mobile, including the real-time 50-second final leg + 20-second descent recordings (`1.2m`).
- Desktop and mobile observation/ending captures, 1366×768 short-viewport WebGL observation and static-fallback captures, real-time handoff/descent recordings (`desktop-handoff-descent.webm`, `mobile-handoff-descent.webm`), and FFmpeg frame samples at 60 s (`118.689 rₛ`) and 70 s (`1.214 rₛ`) in `artifacts/eh-05/` were inspected and verified.
- Environment: headless Chromium on Linux using ANGLE SwiftShader; 1440×1000 desktop and 390×844 mobile CSS viewports, plus 1366×768. Hardware GPU frame pacing was not measured.
- Non-EH-05 artifacts were restored from the pre-test backup so unrelated artifact files were not overwritten.
- Verification servers, browsers and video extraction processes were stopped; ports 5201 and 5210 were verified free.

## Limits

Software WebGL establishes functional behavior and provides visual recordings. It does not establish hardware GPU frame pacing or real-device performance. The existing large JavaScript chunk build warning remains. Full motion preference and context-loss recovery controls belong to EH-06, and the integrated complete journey review belongs to EH-07.
